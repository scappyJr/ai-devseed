# 🔄 Claude.ai ↔ Claude Code 동기화 워크플로우

> AI 협업 1인 개발 프로젝트를 Claude.ai (웹)와 Claude Code (CLI) 두 도구로 효율적으로 진행하기 위한 가이드.
> 본 저장소(AI DevSeed) 자체 개발에도 동일하게 적용.

---

## 🎯 핵심 원칙

> **"왔다갔다 하지 말고, 시간 블록 단위로 분리하라"**

매번 도구를 옮기면 컨텍스트 전환 비용이 커요. 작업 시작 시 "오늘 이 시간 블록에는 어느 도구를 쓸 것인가"를 결정하고 그 안에서 끝내세요.

## 🛠 도구별 역할 분담

### 🌐 Claude.ai (웹) 에서 할 일

**"생각하는" 작업** - 큰 그림, 방향성

- ✅ 새 기능 기획 / 구체화
- ✅ 큰 결정 (아키텍처, 기술 선택)
- ✅ 와이어프레임 / 다이어그램 / SVG 디자인
- ✅ 회고 / 분석
- ✅ 복잡한 논의가 필요한 문제
- ✅ 문서 작성 (긴 글), 마케팅 콘텐츠 (블로그, README, Reddit 글)
- ❌ 코드 작성 / 수정 (Claude Code 더 좋음)
- ❌ 파일 시스템 작업
- ❌ Git 작업

### 💻 Claude Code (CLI) 에서 할 일

**"만드는" 작업** - 실제 구현, 일상 작업

- ✅ 코드 작성 / 수정
- ✅ 파일 / 폴더 작업
- ✅ Git 작업 (커밋, 푸시, 브랜치)
- ✅ 테스트 작성
- ✅ 디버깅
- ✅ ADR 문서 작성 (이미 정해진 결정)
- ✅ 일일 작업 일지
- ✅ 작은 결정 (변수명, 폴더명 등)
- ❌ 큰 기획 (Claude.ai 더 적합)
- ❌ 와이어프레임 그리기

### 🤔 둘 다 가능한 영역

- ADR 작성 (큰 결정은 웹에서 논의 → 코드에서 작성)
- 문서 보강
- 작은 리팩토링

## 📅 일일 작업 패턴

### 🌅 Pattern A: 코딩 위주의 날 (가장 흔함)

```
09:00 - Claude Code 시작
09:05 - /sync-from-web (있다면)
09:10 - /daily 시작
09:15 - 코딩 시작
...
17:00 - /daily 마무리
17:10 - git push
17:15 - 끝
```

**특징**: Claude.ai 안 씀. 가장 효율적.

### 🤔 Pattern B: 큰 결정 + 코딩 혼합

```
09:00 - Claude Code 시작
09:05 - /daily 시작 (오늘 할 일 확인)
09:15 - 어, 큰 결정 필요!
       → /prepare-for-web
       → 프롬프트 복사
09:20 - Claude.ai로 이동
09:25 - 새 대화 시작, 프롬프트 붙여넣기
10:00 - 결정 완료
10:05 - Claude Code로 돌아옴
10:10 - /sync-from-web
       (결정사항을 ADR로 저장)
10:30 - 코딩 시작
...
17:00 - 마무리
```

**특징**: 동기화 명령어로 매끄럽게 전환.

### 💡 Pattern C: 기획/회고의 날

```
09:00 - Claude.ai 시작
       (코드 안 만질 거면 Claude Code 안 켜도 됨)
       단, HANDOFF.md는 미리 읽기
09:05 - 인큐베이터 대화 또는 새 기획 대화
12:00 - 결과물 정리
12:05 - 결과물을 로컬에 저장 (와이어프레임 SVG 등)
12:30 - Claude Code 잠깐 켜기
       → /sync-from-web
       → 변경사항 반영 + git commit
12:45 - 끝
```

**특징**: Claude.ai 위주, Claude Code는 동기화용만.

### 🚀 Pattern D: 출시/베타 작업

```
- 모든 작업이 Claude Code + 약간의 Claude.ai
- 마케팅 글 작성 시: Claude.ai로 글 다듬기
- 실제 출시 작업: Claude Code
```

## 🔄 핵심 동기화 명령어 2가지

### `/sync-from-web`

**언제 쓰나**: Claude.ai에서 작업 후 Claude Code로 돌아왔을 때

**무엇을 하나**:
- 새 결정사항 → ADR 자동 생성
- 새 아이디어 → 적절한 위치로 분배
- 와이어프레임 → wireframes/ 폴더에 추가
- HANDOFF.md 업데이트
- 자동 git commit

**사용**:
```
> /sync-from-web

🌐 Claude.ai에서 작업하고 돌아오셨네요!
다음 중 어떤 게 있었나요?

(인터랙티브 진행)
```

### `/prepare-for-web`

**언제 쓰나**: Claude Code에서 작업 중 Claude.ai로 가야 할 때

**무엇을 하나**:
- 현재 코드 상태 자동 수집 (git log, git status)
- 진행 중인 작업 정리
- 막힌 점 / 결정 필요 사항 추출
- Claude.ai에서 바로 쓸 수 있는 완전한 프롬프트 생성
- 클립보드 자동 복사 (가능한 OS)

**사용**:
```
> /prepare-for-web

🌐 Claude.ai에서 어떤 작업을 하려고 하세요?
1. 큰 결정
2. 새 기능 기획
3. 디자인 작업
...

(목적에 맞는 프롬프트 자동 생성)
```

## 📋 단일 진실 공급원: HANDOFF 파일

프로젝트의 핸드오프 마크다운(이 저장소는 `HANDOFF-aidevseed.md`, AI DevSeed로 init한 프로젝트는 보통 `docs/HANDOFF.md` 또는 `HANDOFF-{프로젝트명}.md`)이 양쪽 도구의 **공유 메모리** 역할.

### 권장 구조
```markdown
## 📍 현재 위치 (Phase, 진행률)

## 🤔 최근 결정사항 (ADR 요약)

## 💭 진행 중인 것 / 다음 액션

## ⚠️ 막힌 점 / 결정 필요

## 🌐 Web → Code (Claude.ai에서 Claude Code로 전달할 것)

## 💻 Code → Web (Claude Code에서 Claude.ai에 전달할 것)
```

> 본 저장소는 위 구조 중 "Phase / 다음 액션 / 주의사항" 위주이고, "Web → Code" / "Code → Web" 섹션은 아직 없음. 필요해지면 추가.

### 황금 규칙
- **양쪽 모두 시작 시**: 이 파일 먼저 읽기
- **양쪽 모두 끝낼 때**: 해당 섹션 업데이트
- **자동화**: 동기화 명령어들이 자동으로 업데이트

### Claude.ai에서 시작 시
```
HANDOFF 파일(예: HANDOFF-aidevseed.md)을 먼저 읽어줘.
특히 "Code → Web" 섹션이 있다면 봐줘.
[이번 세션 목적]
```

### Claude Code에서 시작 시
```
HANDOFF 파일 읽고 /daily 시작 해줘.
"Web → Code" 섹션에 새 내용 있으면 알려줘.
```

## 🎬 실전 시나리오 4가지

### 시나리오 1: "코딩 중 갑자기 큰 결정 필요"

**상황**: CLI 기능 만들다가 "어, plugin 시스템 도입 시점을 어떻게 잡지?"

**대응**:
```
1. 코딩 중단
2. /prepare-for-web 실행 (목적: 1번 큰 결정)
3. 프롬프트 복사
4. Claude.ai에 붙여넣기
5. 1시간 정도 논의, 도입 시점 결정
6. Claude Code로 돌아옴
7. /sync-from-web (결정 → ADR)
8. 코드 작성 재개
```

**시간 비용**: 1.5시간 (그래도 잘못된 결정으로 며칠 낭비하는 것보다 나음)

### 시나리오 2: "주말에 새 기능 기획"

**상황**: 본 작업 진행 중 새 기능/템플릿 아이디어가 떠올랐고, 주말에 구체화하고 싶음

**대응**:
```
[토요일 아침]
1. Claude.ai 인큐베이터 대화로 이동
2. 가벼운 평가
3. "이거 본격 기획해보자" 결정
4. 새 기획 대화 시작
5. 명세/다이어그램까지 받음
6. 결과물 (마크다운 + 이미지) 로컬에 저장

[월요일 아침]
1. Claude Code 시작
2. /sync-from-web
3. 새 기능 명세 → ADR 추가
4. 필요시 docs/images/ 또는 docs/wireframes/ 에 산출물 추가
5. WBS / GitHub Issues 업데이트
6. 다음 작업으로 진행
```

**시간 비용**: 주말 2-3시간 + 월요일 30분 동기화

### 시나리오 3: "Phase 끝 회고"

**상황**: Phase 1 (MVP) 25일 작업이 끝났고, 회고하고 싶음

**대응**:
```
[Phase 1 마지막 날 저녁]
1. Claude Code에서:
   - /prepare-for-web (목적: 4번 회고)
   - 자동으로 4주간 작업 요약됨
   - 막힌 점, 패턴, 변경 결정 등 자동 추출
2. Claude.ai로 이동, 회고 대화
3. 잘된 점, 어려웠던 점, 다음 Phase 우선순위 정리

[다음날]
1. Claude Code로 돌아옴
2. /sync-from-web
3. 회고록을 docs/retrospective/phase-1.md 에 저장
4. Phase 2 작업 시작
```

### 시나리오 4: "단순 코딩만"

**상황**: 오늘은 그냥 코드 작성만 할 거. Claude.ai 안 씀.

**대응**:
```
1. Claude Code 시작
2. /daily 시작
3. HANDOFF.md만 한 번 보고
4. 그냥 코딩
5. /daily 마무리
6. 끝
```

**시간 비용**: 동기화 0분. 가장 효율적.

## 🚦 도구 전환 결정 트리

작업 중 "Claude.ai로 갈까?" 싶을 때 체크:

```
질문 1: 1시간 안에 결정/논의로 해결될 일인가?
  YES → Claude.ai로
  NO  → 더 잘게 쪼개기

질문 2: 코드를 짜야 하는 일인가?
  YES → Claude Code 계속
  NO  → Claude.ai 더 적합

질문 3: 이미 결정 났고 구현만 하면 되나?
  YES → Claude Code 계속
  NO  → Claude.ai에서 결정 먼저

질문 4: 시각 자료 (SVG, 다이어그램) 필요한가?
  YES → Claude.ai (생성 능력 좋음)
  NO  → Claude Code OK

질문 5: 막힌 지 30분 넘었나?
  YES → Claude.ai에서 다른 시각 받기
  NO  → Claude Code에서 좀 더 시도
```

## ⚠️ 흔한 실수 6가지

### 실수 1: 매 결정마다 Claude.ai로 이동
**문제**: 작은 결정까지 웹으로 가면 컨텍스트 전환 비용 큼
**해결**: 변수명, 폴더명 같은 건 그냥 Claude Code에서 결정

### 실수 2: HANDOFF.md 업데이트 안 함
**문제**: 다음 세션에서 컨텍스트 손실
**해결**: 동기화 명령어 사용 (자동 업데이트됨)

### 실수 3: 코드 직접 Claude.ai에 복붙
**문제**: 컨텍스트 손실, 비효율
**해결**: 코드 작업은 Claude Code에서만

### 실수 4: 같은 결정을 양쪽에서 따로 함
**문제**: 일관성 깨짐
**해결**: 큰 결정은 항상 Claude.ai → ADR → Claude Code 한 방향

### 실수 5: 동기화 명령어 안 쓰고 수동으로 다 함
**문제**: 빠뜨리는 게 생김
**해결**: `/sync-from-web` 항상 사용

### 실수 6: 두 도구를 5분 단위로 왔다갔다
**문제**: 컨텍스트 전환 비용이 작업 시간보다 큼
**해결**: 시간 블록 단위로 분리 (최소 1시간)

## 💡 효율 극대화 팁

### Tip 1: 작업 종류 정해놓고 시작
아침에 "오늘은 코딩의 날" 또는 "오늘은 기획의 날" 결정.
혼합은 자제.

### Tip 2: HANDOFF.md를 깔끔하게
복잡해지면 양쪽 동기화 어려움.
정기적으로 정리 (해결된 막힌 점 제거 등).

### Tip 3: ADR을 자세히
나중에 "왜 그렇게 결정했지?" 모를 때 도움.
Claude.ai에서 결정 시 ADR 형식으로 작성 부탁하면 좋음.

### Tip 4: 패턴 인식
본인이 어떤 종류 결정으로 가장 자주 막히는지 보세요.
패턴이 보이면 미리 가이드 만들 수 있음.

### Tip 5: 동기화 비용을 줄이는 방향
- HANDOFF.md를 정확히 유지
- 동기화 명령어 적극 사용
- 큰 결정은 모아서 한 번에 (작은 거 매번 X)

## 📊 동기화 상태 자가 진단

매주 일요일 체크:

```
[ ] HANDOFF.md "마지막 업데이트"가 1주일 이내인가?
[ ] "Web → Code" 섹션이 비어있는가? (다 반영됐다는 뜻)
[ ] "Code → Web" 섹션이 비어있는가? (다 인지됐다는 뜻)
[ ] 최근 ADR이 모두 docs/decisions/ 에 존재하는가?
[ ] Claude.ai 대화 제목들이 명확한가? (나중에 찾기 쉽게)

모두 YES → 잘 동기화 중 ✅
일부 NO → 그 부분 정리 시간 필요 ⚠️
```
