---
description: Claude.ai로 가서 큰 결정/논의를 하기 전, 컨텍스트를 정리해서 복사 가능한 프롬프트 생성
---

사용자가 Claude.ai 웹에 가서 큰 결정/기획/논의를 해야 할 때 사용하는 명령어.
Claude Code의 현재 상태를 정리해서 Claude.ai 새 대화에 붙여넣을 프롬프트를 생성.

## 1단계: 목적 파악

먼저 사용자에게 물어봐:

```
🌐 Claude.ai에서 어떤 작업을 하려고 하세요?

1. 🤔 큰 결정 필요 (아키텍처, 기술 선택 등)
2. 💡 새 기능 기획 (구체화 단계)
3. 🎨 디자인/와이어프레임 작업
4. 📊 회고 / 분석
5. 🐛 복잡한 문제 해결 (혼자 막힌 거)
6. 📝 문서 보강 / 글쓰기
7. 기타

번호로 답해주세요.
```

## 2단계: 현재 상태 수집

자동으로 다음 정보 수집:

```bash
# 1. 최근 작업 (지난 7일)
git log --oneline --since="7 days ago" --max-count=20

# 2. 현재 변경사항
git status --short

# 3. 진행 중인 작업 / 막힌 점 (HANDOFF에서 추출)
grep -A 2 "다음 액션\|막힌\|TODO" HANDOFF-aidevseed.md 2>/dev/null \
  || grep -A 2 "다음 액션\|막힌\|TODO" docs/HANDOFF.md 2>/dev/null

# 4. 미해결 이슈 (GitHub CLI 있을 때)
gh issue list --state open --limit 5 2>/dev/null

# 5. 최근 ADR (있을 때)
ls -t docs/decisions/ 2>/dev/null | head -3
```

> 프로젝트별로 핸드오프 파일명·구조가 다르면 위 grep 대상 경로만 바꿔 쓸 것.

## 3단계: 목적별 프롬프트 생성

> 아래 템플릿의 `{프로젝트명}`·`{한 줄 설명}`·`{기술 스택}` 등은 현재 프로젝트 컨텍스트에서 자동 채움.
> 본 저장소(ai-devseed) 기본값:
> - 프로젝트명: AI DevSeed
> - 한 줄 설명: AI 협업 1인 개발을 위한 프로젝트 스타터 키트 CLI
> - 기술 스택: Node.js 18+ (ESM), Commander.js, @inquirer/prompts, chalk, ora, fs-extra

### 1번 - 큰 결정 필요

```markdown
# 🤔 {프로젝트명} - 결정 필요

## 현재 컨텍스트

### 프로젝트 상태
- Phase: {현재 Phase}
- 진행률: {진행률}
- 현재 작업: {진행 중인 작업}

### 결정해야 할 사항
[사용자가 입력]

### 관련 배경
- 최근 결정사항:
  {최근 ADR 3개 요약, 없으면 "기록된 ADR 없음"}

### 막힌 이유 / 고민
[사용자가 입력]

### 옵션 (생각해본 것)
1. ...
2. ...
3. ...

## 요청
이 결정에 대해 같이 논의해줘:
1. 각 옵션의 장단점
2. 다른 옵션 제안 (있다면)
3. 추천 + 이유
4. 결정 후 영향받을 파일/코드
5. ADR로 작성할 형식 제안

## 참고
- 프로젝트: {프로젝트명} ({기술 스택})
- 한 줄 설명: {한 줄 설명}
- 핸드오프 문서: {HANDOFF 경로} (전체 컨텍스트는 여기 있음)

결정 후엔 Claude Code에서 /sync-from-web 으로 반영할 예정.
```

### 2번 - 새 기능 기획

```markdown
# 💡 {프로젝트명} - 새 기능 기획

## 현재 프로젝트 상태
- Phase: {현재 Phase}
- 핵심 가치 / 사용자: {한 줄 설명}
- 기술 스택: {기술 스택}

## 기획하고 싶은 기능
[사용자가 입력]

### 왜 필요한가
[사용자가 입력]

### 기존 기능과의 관계
[사용자가 입력]

## 컨텍스트 (Claude Code에서 가져옴)

### 최근 작업
{최근 커밋 3~5개}

### 관련 기존 코드/문서
{관련 파일 목록}

## 요청
1. 기능을 더 구체화하자 (1줄 → 1페이지 명세)
2. 사용자 시나리오 작성
3. UX 흐름 그려줘 (필요시)
4. MVP vs 추후 버전 분리
5. ADR 후보 정리
6. 영향받을 기존 코드/문서 식별

작업 후엔 Claude Code에서 /sync-from-web 으로 반영할 예정.
```

### 3번 - 디자인/와이어프레임

```markdown
# 🎨 {프로젝트명} - 디자인 작업

## 디자인 컨텍스트 (있다면)
- 디자인 시스템 문서: {docs/design-notes.md 또는 N/A}
- 톤/스타일 가이드: {한 줄 설명, 없으면 자유}

## 디자인할 화면/요소
[사용자가 입력]

## 기존 화면/자산 (참고)
{docs/wireframes/ 또는 docs/images/ 의 파일 목록, 없으면 "없음"}

## 요청
1. SVG 와이어프레임 또는 다이어그램 만들어줘
2. 기존 디자인이 있으면 일관성 유지
3. 사용자 흐름 고려
4. 필요시 디자인 토큰/원칙 추가 제안

작업 후 결과물(SVG·PNG·마크다운) 받아서 Claude Code에서 `docs/wireframes/` 또는 `docs/images/`에 저장 + /sync-from-web 으로 반영.
```

### 4번 - 회고 / 분석

```markdown
# 📊 {프로젝트명} - 회고

## 회고 대상
[이번 주 / Phase 끝 / 특정 기간 — 사용자가 입력]

## 현재 상황
- 전체 진행률: {진행률}
- Phase: {현재 Phase}

### 완료된 작업
{최근 1주~한달 커밋 요약}

### 미완성 / 막힌 점
{HANDOFF의 막힌 점·다음 액션 섹션}

### 변경된 결정사항
{최근 ADR 변경, 없으면 생략}

## 요청
1. 잘된 점 분석
2. 어려웠던 점 / 막힌 점 분석
3. 패턴 찾기 (반복되는 문제)
4. 다음에 다르게 할 점
5. 다음 Phase 우선순위 조정 제안

회고록 형태로 작성해줘. `docs/retrospective/{날짜}-{주제}.md`에 저장할 예정.
```

### 5번 - 복잡한 문제 해결

```markdown
# 🐛 {프로젝트명} - 문제 해결

## 막힌 문제
[사용자가 입력]

## 시도한 것
[사용자가 입력]

## 코드 상태
- 관련 파일: {파일 경로}
- 최근 변경: {git log -p {파일}로 확인}

## 에러 메시지 (있다면)
```
{에러 전문}
```

## 환경
- Node.js: {node --version}
- npm: {npm --version}
- OS: {OS}

## 요청
1. 가능한 원인 분석
2. 해결 방법 제안 (여러 가지)
3. 디버깅 단계
4. 만약 아키텍처 문제면 ADR로 정리

해결 후 Claude Code로 돌아가서 /sync-from-web 으로 반영 + 코드 수정.
```

### 6번 - 문서 보강 / 글쓰기

```markdown
# 📝 {프로젝트명} - 문서 작업

## 작업할 문서
[사용자가 입력 - 어떤 문서, 어떤 내용]

## 현재 문서 상태
- 위치: {경로}
- 마지막 업데이트: {git log -1}
- 현재 내용 (요약): {파일 내용 첫 30줄}

## 요청
1. 내용 보강 / 재구성
2. 누락된 부분 추가
3. 가독성 향상

## 톤 가이드
- 친근한 1인 개발자 톤
- 언어: {프로젝트 정책 — ai-devseed는 영문 산출물 / 한국어 작업 노트}
- 이모지 적절히
- 구체적 예시 포함

작업 후 마크다운 복사해서 Claude Code에서 해당 파일 업데이트.
```

## 4단계: 프롬프트 출력 + 클립보드 복사

생성된 프롬프트를 마크다운 코드 블록으로 출력:

```
🚀 Claude.ai로 가져갈 프롬프트가 준비됐어요!

다음 내용을 복사해서 Claude.ai에 붙여넣으세요:

═══════════════════════════════════════════════
[복사 시작]
═══════════════════════════════════════════════

[생성된 프롬프트 전체]

═══════════════════════════════════════════════
[복사 끝]
═══════════════════════════════════════════════

💡 권장 흐름:
1. Claude.ai (claude.ai) 열기
2. + New Chat
3. 위 내용 복사 후 붙여넣기
4. 논의 진행
5. 끝나면 Claude Code로 돌아와서: /sync-from-web

⏱️  예상 소요시간:
- 작은 결정: 15-30분
- 큰 기획: 1-2시간
```

## 5단계: 클립보드 자동 복사 (선택)

가능하다면 자동으로 클립보드에 복사:

```bash
# macOS
echo "$PROMPT" | pbcopy

# Linux (xclip)
echo "$PROMPT" | xclip -selection clipboard

# Windows (Git Bash / WSL)
echo "$PROMPT" | clip.exe

# PowerShell
$PROMPT | Set-Clipboard
```

성공 시:
```
✅ 클립보드에 자동 복사됨!
Claude.ai 새 대화에서 Cmd+V (또는 Ctrl+V) 누르면 됨.
```

## 6단계: HANDOFF 업데이트

자동으로 `HANDOFF-aidevseed.md` (또는 프로젝트의 핸드오프 파일)에 다음 항목 추가:

```markdown
- {날짜} {시간}: Claude.ai 세션 시작
  - 주제: {목적}
  - 상태: 진행 중
  - 돌아온 후 /sync-from-web 으로 결과 반영 예정
```

## 사용 예시

```
사용자: /prepare-for-web

Claude: 🌐 Claude.ai에서 어떤 작업을 하려고 하세요?
        [목록]

사용자: 1

Claude: 결정해야 할 사항이 뭐예요?

사용자: CLI에 plugin 시스템을 v0.2에 도입할지, v0.3으로 미룰지

Claude: 옵션을 정리할게요. 생각해본 옵션이 있나요?

사용자:
- 옵션 1: v0.2에 도입, 처음부터 확장성 확보
- 옵션 2: v0.3까지 hardcoded 템플릿만, 출시 단순화

Claude: [컨텍스트 자동 수집]
        [목적별 프롬프트 생성]

        🚀 Claude.ai로 가져갈 프롬프트가 준비됐어요!
        [프롬프트 출력]
        ✅ 클립보드에 자동 복사됨!

        💡 Claude.ai에서 결정 후 돌아와서 /sync-from-web 실행하세요.
        ⏱️  예상 소요시간: 30분~1시간
```
